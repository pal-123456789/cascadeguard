# 🛡️ CascadeGuard

> **See the outage before it happens.** CascadeGuard is an AI system that predicts cascading software failures, identifies their root causes, and recommends the optimal recovery strategy — before the entire system crashes.
>
> Built for **ORCATHON 2026** (Dev Harbour) · Track: Software & AI · Solo: Jay Ghevariya

## 🎯 The Problem

Modern systems don't fail loudly — they fail *sideways*. One saturated connection pool or one leaked heap quietly spreads through dependency chains as retries, pile-ups and timeouts, until a "database hiccup" becomes a full outage. On-call engineers see the symptoms (alerts on 6 services) long before they see the cause.

## 💡 The Solution

CascadeGuard runs a **digital twin of a production e-commerce cluster** (9 services, 13 dependency edges) that degrades under realistic fault scenarios — pool exhaustion, memory leaks, traffic surges, retry storms. Against that live telemetry, a **hybrid AI engine**:

| Module | What it does |
|---|---|
| **Failure Predictor** | Logistic feature-scorer (level + EWMA trend features) + 2-hop dependency-graph risk propagation → per-service failure probability, time-to-failure estimate, and explainable risk drivers |
| **Root Cause Analyzer** | Ranks the *origin* of an unfolding incident by combining anomaly onset time, severity and reverse-dependency path strength — with evidence from logs |
| **Recovery Optimizer** | Monte-Carlo simulates 7 recovery strategies (restart, failover, shed-load, scale-up, throttle, circuit-breaker, cache-bypass) × 30 rollouts each and recommends the optimal one — quantified |
| **Accuracy Tracker** | Every prediction is scored *live* against simulation ground truth: precision, recall and average warning lead-time |
| **Prediction Ledger** | An auditable trail of every warning raised vs. what actually happened — hit, false alarm, or still pending, with the exact warning lead time |

…and renders it all in a **mission-control dashboard**: animated service topology, streaming logs, prediction cards, incident timeline, **business-impact & SLO burn**, a **per-service deep-dive drawer**, one-click strategy application that visibly contains the cascade, and a one-click **Markdown incident report** export.

## 📊 The Killer Metric

The simulation knows which services *actually* fail and when. So every prediction CascadeGuard makes is automatically verified — the dashboard shows **measured precision/recall and how many seconds of warning the model bought** before each failure. No hand-waving AI claims.

Measured on the flagship `pool-exhaustion` scenario (headless harness, `src/core/smoke.ts`):

| Metric | Value |
|---|---|
| Warning lead time before the origin service died | **120 s** of actionable warning |
| Precision / Recall on that scenario | **100 % / 100 %** · 0 false alarms · 0 missed |
| Predicted origin | `orders-db` — the service that actually failed |

Across **all four fault scenarios** (`scripts/evaluate.ts`, seed 42, 12 sim-minutes each):

| Metric | Value |
|---|---|
| Average warning lead time | **75 s** (up to 120 s) |
| Root-cause origin accuracy | **100 %** (4/4 scenarios) |
| Recall — failures caught before they happened | **100 %** — 6 hits, **0 missed** |
| Precision | 75 % (2 false alarms out of 8 predictions — reported as measured, not smoothed away) |

Every number above is regenerated by the headless harness and rendered in the dashboard's **Measured Benchmarks** panel — nothing is hand-written.

## 🏗️ Architecture

```
┌──────────────────────────  Browser (fully client-side)  ─────────────────────────┐
│                                                                                  │
│  Digital Twin Engine            AI Diagnostics (DI-injected)        UI           │
│  ┌──────────────────┐          ┌──────────────────────┐          ┌────────────┐  │
│  │ cluster physics  │ telemetry│ Failure Predictor    │ risks    │ Topology   │  │
│  │ fault scenarios  ├─────────►│ Root Cause Analyzer  ├─────────►│ Log Stream │  │
│  │ log generator    │  600ms   │ Recovery Optimizer   │  ticks   │ Risk/RCA   │  │
│  │ incidents/alerts │          │ Accuracy Tracker     │          │ Ledger     │  │
│  │ metric history   │          │                      │          │ Impact/SLO │  │
│  └──────────────────┘          └──────────────────────┘          │ Benchmarks │  │
│                                       ▲                           └────────────┘  │
│                                       └── DI seam: the engine never imports AI   │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **Engine** (`src/core/engine/`) — deterministic seeded simulation: queueing-style latency curves, retry amplification, pile-up saturation, GC-thrash and leak dynamics, incident lifecycle. Publishes a full-resolution metric series **every simulation step**, which makes the AI's trend features invariant to playback speed.
- **AI** (`src/core/ai/`) — explainable, dependency-injected diagnostics; no black boxes, every score shows its drivers. The predictor never reads ground truth (`metrics.failed`) — only the accuracy tracker does, and only to score itself.
- **Store** (`src/core/store.ts`) — engine singleton + `useSyncExternalStore` React binding; 600 ms real tick = 3 s simulated time.
- **Docs** (`docs/`) — `JUDGE_GUIDE.md`, `ARCHITECTURE.md`, `ALGORITHMS.md`, `evaluation-report.json`.
